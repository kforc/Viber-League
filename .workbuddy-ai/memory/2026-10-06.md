## Viber League — M0–M6 vertical slice BUILT (playable match)

User said "ok build". Built the playable match slice (spec §22 gate), no meta-systems yet.

**Stack as built:** Vite 5 + TypeScript (strict) + Three.js 0.169 + vanilla-TS DOM UI (React intentionally deferred for the slice — the UI layer is swappable). No React deps installed.

**Run:** `npm run dev` → http://localhost:5173. `?autostart` URL param skips title and drops into a match (dev hook). `npm test` = vitest sim suite.

**Key files:**
- `src/sim/` — pure deterministic engine. `constants.ts` (all tuning), `content.ts` (Vibers/formations/clubs), `world.ts` (create + kickoff placement), `physics.ts` (2.5D ball + kinematic players), `ai.ts` (utility-ish decisions + keeper), `engine.ts` (fixed-tick step, phases, goals, commands), `core/math.ts`, `core/rng.ts` (mulberry32).
- `src/render/` — `characters.ts` (chunky low-poly + inverted-hull outline + toon gradient), `pitch.ts` (canvas-texture markings), `renderer.ts` (scene, camera, sync).
- `src/ui/` — `hud.ts`, `screens.ts`, `dom.ts`. `src/app/game.ts` wires everything + fixed-timestep accumulator loop. `src/style.css`.

**Critical conventions / gotchas learned:**
- `sim/` must NEVER import three/DOM — that's the whole architecture. Renderer maps sim (x,y) → world (x=y, z=x); character `rotation.y = p.facing` works because of that mapping.
- Sim must have zero `Math.random`/`Date.now`/`performance.now` — verified by grep. All randomness via `world.rng`.
- Match clock only advances in `phase==='play'`. Half-time STOPS the clock and waits for a `{type:'resume'}` command — headless tests must send it.

**Gameplay bugs found & fixed during build (all caught by tests/screenshots):**
1. Loose-ball control was awarded by *array order* → home team won every 50/50 → 18-0 blowouts. Fix: **nearest player wins** (`engine.ts` control block).
2. Kickoff was a coin-flip tie → home always restarted → runaway. Fix: `world.kickoffTeam` (conceding side restarts), and `resetPositions` uses `KICKOFF_DEPTH` per role so everyone starts in their own half with a proper shape.
3. No tackles lockout → 491 tackles/match ping-pong. Fix: `world.tackleLock` (0.7s global lockout after any tackle attempt).
4. **ROSTER array order didn't match formation slot order** → roles scrambled (Volt at DEF, Moss at FWD). This was the single biggest gameplay improvement: fixing it doubled passes (27→57/team) and cut goals to ~6/match. **Order in `ROSTER` MUST match outfield slot order: DEF, MID, MID, FWD.**
5. Keeper rushing out left the goal open → keepers now hold the line and cover the predicted ball crossing point (`ai.ts` 'keeper' case).
6. HUD flex `space-between` spread all 4 children → possession bar drifted down screen. Fix: wrap top elements in `.hud-top-group`.

**Balance after fixes (8 seeds):** ~6 goals/match, home 24 vs away 26, ~55 passes/side, ~11 tackles/side. Determinism test passes.

**Verification method:** `tsc --noEmit` + `vite build` + vitest. Visual: headless Chrome via CDP (`/tmp/cdp-shot.mjs`, port env `CDP_PORT`) — note Chrome needs `--no-sandbox` inside the tool sandbox, and **rAF barely advances in headless** so screenshots only capture the first moments (fine for layout/visual checks; the sim is validated by Node tests).

**Toolchain gotcha:** the first `npm install` hit a broker timeout and left `node_modules/.bin` EMPTY (packages were fine). Workaround used: invoke binaries directly, e.g. `node node_modules/typescript/bin/tsc`, `node node_modules/vitest/vitest.mjs`, `node node_modules/vite/bin/vite.js`.

**Not built (by design):** club/squad/academy/transfers/league, async PvP, React UI, ESLint boundary rule, PWA manifest.

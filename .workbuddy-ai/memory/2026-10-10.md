## Three real product bugs found and fixed

1. **League table silently clipped 4 of 7 clubs.** `.league-table` /
   `.fixture-list` are flex children of a 390px-tall `.screen.squad-screen`
   column with `overflow: hidden`, so they *shrank* to the leftover space and
   cut off every row past the fold with no way to scroll to them. Fix: `flex: 0 0
   auto` on the table and the list, handing the overflow to the screen, which
   already scrolls (`overflow-y: auto`). Also `flex: 0 0 auto` on `.chip-row`,
   which was being squeezed to 24px and clipping the TABLE/FIXTURES labels.

2. **The result screen's headline was unreachable.** `.overlay-screen` used
   `justify-content: flex-end` **and** scrolled. On a scrolling flex container
   flex-end pushes overflow past the scroll origin, so the outcome, the score
   and the league note were all clipped above the viewport with no way back.
   Same trap as the profile card on 2026-10-09. Fix: `justify-content:
   flex-start` + `margin-top: auto` on the panel (same "pinned low" look, top
   stays reachable) + `overflow-y: auto`.

3. **`DEFAULT_SETTINGS.halfSeconds` was 120, which is not an offered option.**
   `LENGTH_OPTIONS` is 60/90/150, and both the Settings segmented control and
   the minutes screen highlight the entry *equal* to the stored value — so a
   brand-new career opened with no match length selected and played halves no
   option could produce. `game.ts` already defaulted to `LENGTH_OPTIONS[1]` (90).
   Fixed to 90 and pinned with a test that asserts `DEFAULT_SETTINGS.halfSeconds`
   is in `LENGTH_OPTIONS`, so the two cannot drift apart again.

## The `$&` inlining bug (cost the most time)

`tools/cdp/inline-build.mjs` builds the single-file `Viber-League.html` from
`dist/`. Writing it fresh, the app booted to `SyntaxError: Unexpected token '<'`
with `#ui` empty.

Cause: **in `String.replace`, the *replacement* string treats `$&`, `` $` ``,
`$'`, `$$` and `$n` as magic.** The minified Three.js bundle contains
`$&&($[_].dispose(),delete $[_])` — twice. As a string replacement that `$&`
expands to the matched text, splicing a literal `</body>` into the middle of the
JavaScript.

Fix: pass every replacement as a **function** (`() => replacement`), which is
returned verbatim. Plus a guard that reads the embedded script back out and
compares it to what went in — length alone is not enough, because the corrupted
file was byte-for-byte the right size. Verified: 715 kB, 610 kB script body, no
external refs.

## Headless CDP findings

- **Chrome must be started and killed inside the same Bash invocation** as the
  harness (sandbox denies `code_sign_clone (file-delete)`). `tools/cdp/run.sh`
  does this with a `trap ... EXIT`.
- **Wait for HTTP 200 on `/json/version`, not curl's exit code** — a connection
  that is accepted and immediately closed also exits 0, and the harness then
  starts against a socket that is not serving CDP. This produced a confusing
  `ECONNREFUSED` from `fetch`.
- **Do NOT add `--disable-frame-rate-limit`.** It reliably wedges
  `Page.captureScreenshot`. `--run-all-compositor-stages-before-draw` wedges the
  page outright. Plain headless runs rAF at ~58-60fps; an early measurement of
  8 frames / 5s was misleading.
- **A live match is slow but drivable.** Software WebGL (swiftshader) plus the
  sim's 0.05s timestep clamp means roughly 1-2fps. Measured with `halfSeconds:
  1` and clear weather: **half-time at 19s, full-time at 31s**. **Rain is ~5x
  slower again** — its particles are brutal in software — which is why an
  earlier `weather: 'random'` run appeared to stall. The harness pins
  `halfSeconds: 2, weather: 'sun'` for the loop; the 60-second half is verified
  separately by the settings checks.
- Screenshot timeout needs ~45s during a match (the renderer is saturated).

# Phase 4 — sound, and faster keep-ins

Task: *"now add some sounds ... like real sounds for goals, whistle, then add
noise from crowds. Also make the characters faster to stop balls before
entering throw ins."*

## Part 1 — keep-in speed (done first, measured)

`KEEP_IN_REACH = 2.2`, `KEEP_IN_HORIZON = 1.7`, `KEEP_IN_SPRINT_MULT = 1.2` in
`sim/constants.ts`, plus `ballExit()` in `sim/physics.ts` and a `keepInAssignment`
errand in `sim/ai.ts` that sends exactly one *entitled* player (per the shared
`restartTaker`) sprinting for the crossing point. Measured over 6 matches:
throw-ins **15 → 8 (-47%)**, corners unchanged at 49, 2.5 goals/match.

## Part 2 — the sound engine

`src/audio/sound.ts`. **No audio files** — `tools/cdp/inline-build.mjs` fails the
build if any external reference survives into the bundle, so everything is
synthesized from Web Audio primitives.

- **Whistle** = band-passed noise (the air through the slot) + a near-sine at
  ~2.1 kHz plus its octave (the tone) + a 36 Hz amplitude trill (the pea). The
  trill is what makes it a whistle rather than a test tone.
- **`WHISTLE_SCHEDULE`** holds the *shape* per kind: kickoff 1 blast, goal 1,
  foul 2, halftime 2, fulltime one long one. The sim emits
  `{type:'whistle', kind}` and the engine looks up the pattern.
- **Crowd** = two readers of one pink-noise buffer (Kellet filter bank) half a
  buffer apart so they never phase-lock: one low-passed into a rumble, one
  band-passed into the hiss, plus a 0.11 Hz wobble so it breathes. Level drives
  gain **and** both filter cutoffs — an excited crowd is brighter, not just
  louder.
- **Goal** = three noise bands arriving at different speeds (low swell 0.3 s
  attack, mid roar 0.07 s, high scream +0.05 s). One band of filtered noise
  sounds like static; three that grow at different rates sound like people.
- **`CrowdHeat`** is the pure, testable part: `excite(jolt)` from events,
  `step(dt, ballAdvance)` for the drift. AMBIENT 0.2, ADVANCE_WEIGHT 0.42,
  DECAY 0.55/s. The ball's position is deliberately weighted *below* a goal so
  the crowd does not roar continuously.
- **Lazy + gated.** No `AudioContext` until `unlock()`, which is called from the
  KICK OFF tap. `unlock()` returns immediately **while muted** — a muted career
  builds no graph at all, and switching sound on is itself a gesture so that is
  where the context starts.

## Bugs / traps hit this phase

1. **A muted game must not build an AudioContext.** First draft built it anyway
   and merely set master gain to 0. Fixed by early-returning from `unlock()`.
   This is also what makes the e2e assertion possible (`constructed === 0`).
2. **Two of my own test assertions were wrong, not the code.** `excite(1)`
   clamps the level at 1, which hid the decay the test was measuring (use 0.5);
   and `fulltime 1.15 s > longest other × 1.8` failed because halftime is 0.68 s
   (1.15 / 0.68 = 1.69) — the factor was the error, not the duration.
3. **`halfSeconds` in a hand-written test fixture.** `withSettings` now returns
   `sound` too, so an exact `toEqual({...})` on the settings object broke. Exact
   `toEqual` on a settings bag is a maintenance trap; list the fields.

## Harness additions

- `Page.addScriptToEvaluateOnNewDocument` wraps `AudioContext` **before the
  game's module runs**, recording `constructed` / `resumed` / `state`. That is
  how "the kick-off gesture builds the graph" and "a muted career builds nothing"
  are both asserted — neither is observable from inside the game.
- `resumed` counts *calls*, not successes: a synthetic `MouseEvent` is not
  trusted user activation, so headless Chrome keeps the context `suspended`.
  That is browser policy, not a product bug, and the harness does not assert on
  it. A real `Input.dispatchMouseEvent` would be needed to hear anything.
- The half-time resume check used a fixed 1.2 s sleep. Software WebGL runs the
  match at ~0.2× real time, so one frame can be most of a second — the wait sat
  exactly on that boundary. Now it polls for up to 20 s, and is split into two
  checks (panel closed / half is 2) so a failure says which half broke.

## In-match mute

`ui/hud.ts` gained a `.sound-btn` beside SPECIAL and pause — without it the only
way to silence the ground mid-match is to leave the match. It shares
`.pause-btn`'s styling, and muted is the **same glyph struck through**
(`text-decoration: line-through`), never a second character: swapping glyphs
would change the button's intrinsic width and shift the row. `Hud.setMuted()` is
the only thing that decides the button's state; a tap reports the requested
value and the game pushes the truth back.

## Two more things the screenshots caught

1. **`SUNNY · 0.06666666666666667min`** in the HUD conditions strip —
   `(w.halfSeconds * 2) / 60` with no formatting. Every offered length is a whole
   number of minutes, but `sanitiseSettings` accepts any positive number, so the
   harness's 2-second half rendered the raw float. Now `displayLength()`.
   *Look at the screenshots; the numbers catch what the assertions do not.*
2. **`kick(power)` was a dead parameter.** The doc comment claimed "a pass is
   softer than a shot", but nothing ever passed anything — `special` is a buff
   event, not a shot, so `shot` is the only caller and it is always the same
   event. Removed, and replaced with a ±6 % detune on the strike so twenty shots
   in a match do not sound like one sample played twenty times.

## Tests for the whistle — closing the loop on dead code

`{ type: 'whistle' }` sat in `SimEvent` unused; the fix added emission but no
test would have noticed if it regressed. Added:

- `tests/sim/match.test.ts` → `describe('the referee')`, 3 tests off one match:
  kickoff ≥ 2 (one per half), halftime and fulltime present; every kind emitted is
  one of the five the audio layer knows; and **every whistle is adjacent to its
  moment** — immediately before it, except `goal`, which is deliberately after
  (the roar starts first and the blast cuts across it).
- `tests/sim/setpiece.test.ts` → a foul pushes `whistle(foul)` as `events[0]`,
  before the `foul` event that says who did it, and blows exactly once.

# Phase 5 — the club identity, and the official logo

crest field added to the same form. **Probe before you build.**

## The placeholder text was one line, not a system

`renderTitle`'s club line was hardcoded as `` `${PLAYER_CLUB.name} · 5-a-side` ``.
Now it shows the player's own club and crest, and renders **nothing** for a guest
rather than a stand-in. Also purged the invented club name at source:
`PLAYER_CLUB` in `sim/content.ts` was `'Vibe Vibe United' / 'VVU'`, and is now
`'Your Club' / 'YOU'` — an honest "you have not set one" rather than filler that
reads as generated content. `hud.ts`'s pre-`setTeams` literals changed to match.

## `src/brand.ts` — one geometry, two renderers

A new root-level module (beside `sim/`, because both `ui/` and `render/` need it
and neither may import the other). The official mark and six club crests are
**SVG path strings**, and those strings are the single source of truth: the DOM
renderer emits `<path d="…">`, the canvas renderer does `new Path2D(d)` on the
identical strings. `Path2D` is only touched inside `drawBrand()`, so the module
stays importable in Node for the unit tests.

Not an image file, because the bundle must stay self-contained
(`inline-build.mjs` fails on any external reference) — a data-URI PNG would pass
that check but bloat the file and lose its edge at every size.

**Judged by rendering, never by assumption.** The Viber head took two correction
rounds against `docs/screens-brand/brand.png`: first it read as a flat blob, then
as a merged "VN". The fix was a distinctly *narrower* band under the lobes, then
a *wider* head (62 units) with bolder, better-spaced V/V marks.

## The logo, placed

- **On the pitch**: mown into the centre circle in two grass tones (white paint +
  a darker green cut-out, inverted on snow). Painted onto its own canvas and
  composited at low alpha, because the face is made of *cut-outs* — painted
  straight onto the turf the near-black ink lands as a smudge.
- **Around the pitch**: black hoardings with a lime rule, the mark, and an
  auto-fitted `VIBER LEAGUE` wordmark. Two jobs, two placements — touchlines
  (glancing angle; the point is the plate standing out among the pastel sponsor
  blocks) and either side of the far goal (near face-on, the only place the
  wordmark reads).
- **First attempt was wrong twice, and the screenshots said so.** The centre
  emblem at 1.34× the circle radius read as a smudge, and the single byline board
  sat directly behind the goal net (2.2 m tall) which swallowed a 1.4 m board
  whole. Fixed: 1.72× radius, and two byline boards at x = ±7.6.

`paintBrandBoard` lives in `brand.ts` (drawing) not `stadium.ts` (layout), which
is also what lets `probe-brand.mjs` render the face standalone. It repaints on
`document.fonts.ready` — the display face ships as a data-URI `@font-face` and
still loads asynchronously.

## Traps hit

- **`outerHTML` on a `<canvas>` serialises the element, not its bitmap.** The
  first version of the probe's board row came back blank. Append the live node.
- **A backtick inside a template literal**, in a code comment, terminates the
  literal. Cost two "missing ) after argument list" cycles in `probe-brand.mjs`.
- **`as IconDef & { fill2: string[] }`** was a leftover from a draft needing two
  fill colours; folded into the plain interface.
- The `.crest-badge` used to *be* the lime abbreviation chip. Now the badge is the
  real logo and the abbreviation needs its own plate, so `.crest-short` was born
  and `.crest-badge` became a bare holder — painting a second plate behind a mark
  that draws its own badge would double the frame.

## The eyes, and the V/V that came with them

The user was right: the rendered mark had **no eyes**. The bug was a category
error, not a size error — they were authored as `cut:` (ink discs drawn on the
ink badge), which is invisible by construction. The reference was measured
pixel-by-pixel with Pillow and the eyes are **lime fills** sitting on the badge
*below* the head: `circlePath(37.8, 69.9, 3.8)` and `circlePath(61.7, 68.7, 3.8)`,
tilted −3.00°. Measuring them exposed a second inaccuracy — the V/V was 2.3× too
tall (34.9 × 13.7 units in the reference), a "legibility beats fidelity" call
that had made the lettering far louder than the artwork. Both fixed. `brand.ts`
now documents the lime-not-cut trap in a comment so it cannot regress.

## Catchable penalties: two phases, not one roll

`takePenalty` used to resolve with a single `w.rng` roll. It now **launches a
real ball** and never returns a score. The seam is the existing command queue:

- `phase: 'penalty'` — `w.paused = true` (the `enterHalftime` pattern), overlay
  renders `renderPenaltyDive`, the choice is queued as `{ type: 'dive', team: 0,
  value }` and the world is unpaused in the same click.
- `phase: 'penaltyshot'` — `advancePenaltyShot` integrates the ball, slides the
  keeper laterally by `diveY * min(1, elapsed / 0.25)`, and tests contact at the
  **exact keeper-line crossing by interpolating `t`** — so the outcome does not
  change under a smaller fixed timestep. A correct read sets `ball.owner` to the
  keeper and emits `{ type: 'save' }`; a wrong one is beaten.
- `advanceClock` was extracted so the clock runs through both open play and the
  in-flight shot; `step()` early-returns for `penaltyshot` so no outfielder can
  scoop the ball up mid-penalty.

`applyCommand`'s `dive` case is guarded to `w.setPiece?.kind === 'penalty'` and
the defending human only — a late or spoofed command cannot rewrite a shot.

Verified: `setpiece.test.ts` scans seeds 1–48 for one where `left` catches and
`right` is beaten on the same seed, with an exact replay. The browser probes
passed in **both** orientations (0 failed checks, 0 page errors); the portrait
run happened to resolve to `phase: "play", ballOwner: 1` — a live catch.

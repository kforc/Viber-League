# 2026-10-08 — Viber League: Phase D UI/visual refinement

## Landmark fixes (layout)

**Landscape hero-select became two columns.** Stacked in a 390px-tall viewport the
card rail was left ~90px and every card clipped its name/role row. Now a CSS grid:
`head` spans, `stage` (3D hero) owns the left column, `body` (chips + rail) the
right, `foot` spans. Required wrapping chips+grid in a new `.hero-body` div in
`renderSquadSelect` (screens.ts) so the grid has a single child per area.

**Landscape venue picker became two columns** (preview left, venue list right).
Stacked, the three bands totalled ~450px in a 390px viewport: the sticky
`.flow-actions` rode up over the rail and `preserveAspectRatio: slice` cropped the
artwork so hard that only the crowd survived — the goal sat behind the name plate.
The rail also turns into a vertical list of compact rows (thumb 52x39 + name).
Root cause of the crop: scene was 812x187 (4.34:1) against a 400x240 viewBox, so
scale was 2.03x and the visible original y range was 74..166, of which the plate
covered 107..166 (goal at y=110, box at 126..153). At 502x258 the scale drops to
1.26x and the whole ground is legible.

## Specificity trap (worth remembering)

`.screen.hero-select .viber-grid` (0,3,0) sets `overflow-x: hidden`. A landscape
override written as `.hero-select .viber-grid` (0,2,0) LOSES, and the horizontal
rail is clipped instead of scrolled. Landscape overrides must repeat the full
base selector chain. Same for `.screen.venue-screen`.

Also: `.screen` is `display:flex; align-items:center`, so any grid override must
re-set `align-items: stretch; justify-items: stretch` or children shrink-wrap.

## Environment gotcha: Page.captureScreenshot is dead here

Screenshots hang indefinitely under SwiftShader because the app's rAF render loop
means the compositor never settles. It worked at 08:35 today and stopped working
after; `--user-data-dir`, pausing the virtual clock, and dropping the swiftshader
flags all failed to bring it back. **Do not rely on screenshots for UI
verification in this environment — use DOM geometry probes.** Always wrap
captures in a hard timeout so a hang degrades to "skipped".

Memory pressure: `tsc`/`vitest` die with SIGTERM (exit 137) when free pages are
low. Leftover headless Chrome instances are the usual culprit — check
`lsof -nP -iTCP:9222-9231 -sTCP:LISTEN` and kill stale ones.

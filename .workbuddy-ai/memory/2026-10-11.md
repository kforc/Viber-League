## Goal celebrations (user request: "add the vibers celebrations after each goal, a very short one")

window (no new phase, no new timer — the goal phase already freezes play and lasts
`GOAL_PAUSE`). Files touched:

- **`src/render/characters.ts`** — new `applyCelebration(rig, t, seedId, weight)`.
  Arms pivot at the shoulder and hang down, so raising them overhead is

  as one: (a) both fists overhead, (b) right fist up + left out, (c) arms splayed

  goal window (weight 0 at the exact goal tick, so it eases in). Driven off
  `GOAL_PAUSE - world.phaseTimer`; only the scoring side (`world.lastGoalTeam`)
  celebrates. Camera now pushes in on the goal: `camBack`/`camHeight` ease at
  12%/frame toward `GOAL_CAM_BACK` (11) / `GOAL_CAM_HEIGHT` (8) by `goalK`, then
  pull back before the restart. Push-in is **aspect-aware** (`NARROW_MIN`/`MAX`
  scale `GOAL_CAM_BACK` by `clamp(1/aspect, 1, 1.15)`) — a portrait viewport
  crops the near Vibers otherwise. Camera is framed on the ball's end, NOT the
  celebrating side's centroid (that swung it to the wrong half when players were

- **`src/ui/hud.ts` + `src/style.css`** — `.hud.celebrating` fades `.mentality-row`,
  `.action-row`, `.special-btn` to opacity 0 (they are inert while the ball is

  Transition declared on an always-matching rule so the fade-back is smooth too.
- **`src/app/game.ts`** — added a `?seed=<n>` dev hook alongside `?autostart` /

## Gotchas learned (worth keeping)

- **Headless frame pumping.** The app's rAF loop does NOT run in the headless
  page; frames only advance when a `Page.captureScreenshot` forces one. Probes
  must screenshot *before* reading rig state. (Earlier debug probe set
  `rigs[0].armL.rotation.x = 99`, waited 250ms, still 99 → sync never ran.)
- **Drain sim events during headless stepping.** Stepping the sim for thousands of
  ticks without the app consuming events builds a backlog; on the next real frame
  the app replays it (a stale `halftime` event once covered the celebration). The
  probe drains non-goal events and hands the app only the goal.
- **Effective opacity ≠ computed opacity.** `getComputedStyle(child).opacity`
  returns the child's own value, not the ancestor-multiplied rendered value. A
  probe reading `.mentality-btn` reported 1 while the faded `.mentality-row`
  parent made it invisible. Measure by walking up and multiplying.
- **Two software-WebGL Chrome instances in parallel starve each other** —
  `Page.captureScreenshot` TIMEOUT. Run heavy CDP harnesses sequentially.
- `npm run shots` / probes still report shell "failed" when green (sandbox denies
  Chrome's own RLZ/GoogleUpdater deletions). Verdict = the `=== N failed check(s) ===`
  line + `report.json`.

## Bug fix: penalty aim/dive screen-axis loop hole (commit 5fbee79)

User reported: "shoot left, viber went right, they caught it" + mirror case on
conceded pens — a save loop hole. Root cause = **camera/screen-axis inversion**,
not the save math. The +Z camera mirrors world +Y onto the screen's LEFT, so the
old `laneY = left?-1.35 : right?+1.35` made a 'right' pick launch to world +Y,
which RENDERS on screen-left. Labels looked reversed; the keeper read the same
lane, so opposite-world picks still met. Save geometry was always correct.

Fix (both flip together, so save geometry unchanged):
- `setpiece.ts` takePenalty: `laneY = left?1.35 : right?-1.35 : 0`
- `engine.ts` advancePenaltyShot: `diveY = left?1.35 : right?-1.35 : 0`
Now 'right' -> world -Y -> screen-right, 'left' -> world +Y -> screen-left,
matching the labels. Verified:
- setpiece test updated: `vyRight<0`, `vyLeft>0`, `vyRight<vyLeft` (14 tests green).
- New regression probe `probe-penalty-save.mjs`: right->vy<0, left->vy>0, AND
  misaligned keeper dives still concede GOALS (loop hole closed). 0 failed.
- `probe-penalty-shoot.mjs` stale assert (`vyRight>vyLeft`) fixed to
  `vyRight<vyLeft && <0 && >0`; re-ran 0 failed. `probe-pause.mjs` re-ran 0 failed.
- `npm run bundle` self-contained (739 KB).

Gotcha: running >1 CDP probe that launches Chrome in PARALLEL races port 9333
(ECONNREFUSED). The earlier shoot-probe "1 failed" was a stale assertion, not a
regression; the pause-probe crash was the parallel port race. Run probes serially.

## Realism pass: finishing, keeper saves, power, arrangement (user request)

User (footballer's eye): clear chances were ending up at the corner; keeper
defence unrealistic; wants more shot power so goals come from anywhere; and the
team's *arrangement* should visibly match the chosen mentality (4: attack /
balanced / defend / counter).

Four changes, all in `sim/` (deterministic, rng-only):

1. **Shooting accuracy (`engine.ts` handleCarrier 'shoot')** — was
   `spread = (0.95 + dGoal*0.3)*skill` (huge even close) + a random ±1.2 corner
   offset, so clear chances sailed wide. Now three explicit tiers:
   `clear` (dGoal<8 && pressure>2.6): `0.16 + (1-acc)*0.5` (pinpoint);
   `long`: `0.55 + (1-acc)*1.8` (aimed at a corner, ~2/3 on target);
   `other`: `1.0 + (1-acc)*3.8 + dGoal*0.06` (genuinely wayward → corners).
   `acc = shooting*0.55 + space*0.3 + (1-dGoal/20)*0.25`. Aim clamped to
   ±(GOAL_HALF_W+2.2) so misses are near the goal, not the corner flag.
2. **Power** — `SHOT_SPEED` 25→28, `BALL_MAX_SPEED` 34→42, new
   `LONG_SHOT_POWER=1.24`. Long shots are hit harder, so a placed long shot
   beats the keeper → goals from range.
3. **Keeper (`engine.ts` tryKeeperSave + `ai.ts` moveTarget 'keeper')** — was a
   probability roll (`bd<=KEEPER_SAVE_REACH` → `0.22+reflex*0.42` held). Now
   **geometric**, mirroring the penalty model: at the keeper line, save iff
   `|contactY - keeper.pos.y| <= 0.95 + reflex*0.55` (interpolated contact).
   Keeper positioning now tracks the ball's *projected crossing y* (angle cut)
   instead of `b.pos.y*0.5`. The loose-ball loop no longer lets a keeper collect
   a fast beaten shot (only speedNow<=9), so a shot past them is a goal.
4. **Arrangement (`constants.ts` MENTALITY_SHAPE + `ai.ts` supportTarget +
   `world.ts` resetPositions)** — was a uniform ±2.6m `push`. Now per-role depth
   + whole-team depth + width + compact, so attack lines up high & wide, defend
   sits deep & narrow, counter compact between them. Kickoff applies the
   whole-team depth only (per-role would pile everyone on the halfway line).

Measured (tools/measure-balance.mjs, 10 seeds × 250s): **goals/match 5.1,
onTarget 82%, longGoals/match ~0.9, saves/match ~36**. Tests: new
`tests/sim/tactics-shape.test.ts` (3). Full sim suite 68 green (match 15,
setpiece 14, gameplay 7, league 29, tactics 3). New probe
`tools/cdp/probe-arrangement.mjs` (0 failed; kickoff shape + live shape).
`npm run bundle` self-contained (740 KB).

a mentality command, or every capture silently keeps the previous mentality.
The in-game broadcast camera + centre banner make a still frame a poor way to
*show* the shape; trust the numbers, not the PNG.

### The reported bug — a token-name trap

`.menu-btn.primary { color: var(--ink) }`. In THIS codebase `--ink` is the
**light** text colour (cream `#f3e6c4`) — the reference project calls its dark
colour `--ink`, and the rename was never done. So the lime RESUME button was
**cream on lime = 1.04:1**, i.e. a blank yellow bar. Every other lime surface
already used `--on-lime`; this was the one that did not. Now **16.3:1**.

Audited every lime-background rule for its text colour afterwards: only that one
was wrong.

### Player cards — restructured into four bands

Was a centred pile: the `+` quick-add overlapped the role pill, the rating plate
collided with the avatar, and the selected state stamped BOTH a green tick and a
pick number. Now, top to bottom:

1. `.card-top` — rating plate left, and a reserved right corner (`padding-right`)
   for `.card-add`. The add control is a **sibling** of the card button, not a
   child (nesting a button in a button is invalid HTML), so it is absolutely
   positioned against `.card-slot`.
2. `.card-art` — the avatar window; the floor glow moved from `.viber-card2::after`
   to `.card-art::after` so it tracks the art, not the text below it.
3. `.card-meta` — name + epithet, both clamped to one line.
4. `.card-role` — full-width bar (was an inline pill). It cannot be landed on.

Selection is now ONE marker: `.card-pick` (the squad slot number). Its *presence*
is the cue, so the state still reads for someone who cannot separate the lime
frame from the card fill. `.card-check` / `.pick-num` are gone.

### Two measured layout bugs (do not guess these)

- **`.card-name` clipped 3px vertically.** `.card-meta` had `line-height: 1.15`
  but **Baloo 2's inline content area is ~1.36em**, so the children's
  `overflow: hidden` (added for the ellipsis clamp) shaved the glyphs:
  `scrollHeight 19` in a `clientHeight 16` box. Fix: `line-height: 1.4`. The
  probe's clip detector reports `scroll = scrollHeight x scrollWidth` and only
  fires when `overflow !== visible && delta > 2` — landscape squeaked by at 2px,
  portrait failed at 3px. Both green now.
- **A picked card was clipped by the landscape rail.** The base selected state is
  `translateY(-5px) scale(1.035)`; in the landscape rail (`overflow-x: auto`
  forces `overflow-y` to clip, so the lift can never simply show) the card's
  centred position left no headroom and the top border + rating plate were cut.
  Fix: bias the rail's vertical padding to the top (`5px 2px 3px` instead of
  `3px 2px 5px`) to buy headroom, and drop the landscape selected state to
  `translateY(-4px)` with no scale. Measured `railOverflow` +5 → -1.
  **A transform does not change `scrollHeight`**, so the existing clip detector
  is blind to this class of bug — added an explicit rail-vs-card check instead.

### Inclusiveness layer (new section at the end of `style.css`)

- `:focus-visible` ring on every control; lime-on-lime surfaces flip the ring to
  cream.
- `.card-add::after` — a 44px invisible hit area centred on the small button.
- `@media (prefers-contrast: more)` — lifts `--ink-dim`/`--ink-mute`, makes the
  panels opaque, drops the scrim.
- Type floor: every `font-size` below 9px raised to 9–9.5px. `.text-input` 14px →
  **16px** (below that, iOS Safari zooms the viewport on focus and strands the

- `--ink-mute` 0.38 → 0.55, `--ink-dim` 0.62 → 0.68 (~3.2:1 → ~5.1:1 / ~7:1).
- `.panel-title.draw` / `.defeat` gradient dark stops lightened (`#5d6b57` →
  `#8b9c84`, `#991b1b` → `#cf4444`).
- `.primary-btn:disabled` text 0.32 → 0.5; `.menu-btn:disabled` opacity 0.42 → 0.58.
